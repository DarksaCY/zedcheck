# zedcheck — диагностика камеры ZED M

Работает без ZED SDK: читает USB напрямую из sysfs, перечисляет режимы V4L2
собственными ioctl (без `v4l2-ctl`), картинку берёт через OpenCV/UVC.

## Использование

    ./run.sh                    # веб-панель на http://127.0.0.1:8420
    .venv/bin/python report.py  # то же самое текстом в консоль

## Что показывает панель

- вердикт по камере: виден ли UVC-видеоинтерфейс или только HID (IMU);
- топология шин USB со скоростями — видно, воткнута ли камера в USB 3.0;
- полный список режимов каждого узла `/dev/video*` (FourCC, разрешения, fps);
- живой поток MJPEG с выбором разрешения, формата и ракурса
  (левый / правый глаз, оба, анаглиф, разница L−R) — ZED отдаёт стерео
  одним кадром side-by-side, панель режет его сама;
- измеренный fps против заявленного драйвером, счётчики кадров и ошибок,
  и — важно — совпало ли выданное разрешение с запрошенным;
- «Прогнать все режимы»: перебор 2.2K / FHD / HD / VGA с отчётом,
  какие реально поднялись.

## Ожидаемое USB-имя

ZED M занимает **два** USB-устройства. Оба должны присутствовать:

| VID:PID     | Что это                          |
|-------------|----------------------------------|
| `2b03:f680` | UVC-видеоинтерфейс — даёт картинку |
| `2b03:f681` | HID-интерфейс — IMU              |

Если есть только `f681` — камера сидит на USB 2.0 (или на USB 2.0
кабеле/хабе). Видео на USB 2.0 не поднимается вообще.

## Глубина и SDK

Панель даёт сырое стереоизображение. Карта глубины, калибровка и позиционное
отслеживание требуют ZED SDK (сейчас не установлен) и NVIDIA CUDA.
